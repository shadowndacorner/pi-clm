## Levers (each cites a concrete step)

- **L1 — Verification economy.** E2 steps 5–11 and E6 step 7 changed no graded bytes; the reward was already earned (E2 step 3, E6 step 5). Cap: the task's own check or one `cat`; at most ONE independent confirmation when a pass is surprising. Predicted: turns ↓ on the E2/E6 class, accuracy flat.
- **L2 — Answer-sized output.** E4's answer came from the step-9 aggregate, never from the step-7 dump; E5's deliverable needed five grep hits, not the step-3 full read. Predicted: per-turn input tokens ↓ sharply (E5 ~1417 → ~200); accuracy held only with a widen-once floor.
- **L3 — Single-pass compute, recon only under ambiguity.** E4 steps 4–10 = four passes where one suffices; E3 step 2 = recon with zero ambiguity. Predicted: turns ↓ ~2 per data task.
- **L4 — Mirror hygiene.** E6 steps 11 and 15: first uniqueness failure is a stop signal; one EOF append or skip. Predicted: removes E6's three post-solution turns (steps 6–8).

name: one-check-done
description: Turn-count lever — collapse verification and multi-pass probing to one decisive check per task; targets E2 steps 5–11 (4 redundant probes after exit-0 at step 3) and E6 step 7 (post-solution hexdump); predicts turns/cost down, accuracy flat.
---
# Working discipline (each rule fires on its trigger; no standing ritual)

1. Trigger — first action: name the graded artifact and the grader. If the task names a check command, that command is the ONLY verification that matters. If it names a file + content, byte-exactness is the grader. Everything before the artifact exists is compute, never checking.
2. Trigger — counting, searching, or math over data: do it in ONE shell pipeline whose stdout is only the answer (`grep -l`, `awk '{s+=$1} END{print s}'`, `sort | uniq -c`, a run-length awk). Chain filters in a single command; never run a second exploratory pass to "see" what the first already computed.
3. Trigger — you want to look before acting: recon is allowed only if the task leaves the target genuinely ambiguous (unknown path, unknown schema). If the task already states the file's name and state, act on that statement directly.
4. Trigger — the task's check command exits 0 / prints all-pass: STOP. Investigate nothing, change nothing, reply DONE with a one-sentence report of the passing state. An unexpected pass is still a pass: you may run at most ONE independent confirmation (call the function once, cat the file once), and only if that confirmation contradicts the pass do you continue.
5. Trigger — you wrote a file the grader reads: confirm with one `cat` of that file (or of the graded line). Never hexdump, stat, wc-proof, or re-derive the content; the write tool's success plus one cat is decisive.
6. Trigger — artifact written and confirmed: reply DONE with no further tool calls. DONE is a one-word turn.

name: answer-sized-io
description: Bytes lever — never ingest whole files, cap every command's stdout to answer-size, touch the live-context file once at EOF or not at all; targets E5 step 3 (full 60-entry read), E4 step 7 (36-item dump), E6 steps 11/15 (failed mirror-edit loop); predicts per-turn input cost down, accuracy held via widen-once floor.
---
# Working discipline (each rule fires on its trigger; no standing ritual)

1. Trigger — tempted to read a file: don't. Pull only what the deliverable needs: grep the exact tokens with one line of context, `head`/`tail` a 5-line sample. For "must mention these words" tasks, the grep hits plus one sample ARE the entire research phase.
2. Trigger — any command about to run: its stdout must be the answer, not the evidence. Aggregate inside the pipeline (awk sums/counts/run-lengths, `sort | uniq -c`, `grep -c`) so output stays under ~10 lines. Never enumerate rows, positions, or a whole log.
3. Trigger — a targeted query returns nothing or looks ambiguous: widen EXACTLY once (drop one constraint, raise the line cap). Only if the second query is also empty do you read the file, and then in head/tail windows. Skipping this floor is the one way this discipline loses accuracy — never guess from a silent grep.
4. Trigger — writing the graded file: use the write tool with exactly the graded bytes (exact strings, exact JSON punctuation, no extra lines). One `cat` of the file afterwards is the whole verification.
5. Trigger — the live-context file: touch it at most once, and only if the task explicitly asks for notes/running state. Append at end-of-file in one command (`printf '%s\n' "notes: ..." >> <ctx>`); never edit text inside it, never re-anchor a failed edit — if an operation on it errors once, abandon it. Notes are not graded; the deliverable is.
6. Trigger — deliverable exists and passed its one cat: reply DONE immediately; no exploration after the artifact.
